# Project Overview 2026-02-13

This is a first-pass map of core runtime, workflows, and code style based on current source and docs. It focuses on app.js, routes, controllers, and module.

## Snapshot

- Stack: Node.js, Express, MariaDB, EJS templates, SSE
- Data model: clients, orders, products, users, sessions, tokens, posts, facts
- Architecture state: legacy routers are active; refactored controller/service pattern exists in parallel but is not fully integrated
- Localization: session-based language switch with JSON files in ui/

## Runtime Map

### Entry Points

- app.js: main server, middleware, session store, routing, DB init, default admin creation
- config/index.js: centralized environment configuration and validation (not yet wired into app.js)

### Session and Auth

- express-session with MySQL store
- session user class gates routes via module/session/sessionClass.js
- login flow sets session.userid and session.userclass

### Routers (Active)

- / (login, session check)
- /app: UI content, product list, localization payloads
- /client: client search, login, order flows
- /manage: product and client management, reporting utilities
- /accountant: reports, archive data, backups
- /mboard: message board (posts, images, bots, QR)
- /remoteMboard: remote board access (session-gated)
- /events: SSE channel for live refresh events
- /secretadminpanel: admin user creation

### Data Layer

- module/database/db.js is the legacy DB API (direct queries)
- module/database/*Repository.js is the refactored repository layer (parameterized queries)
- module/models/* are data models used by services
- services (ClientService, OrderService, ProductService) implement business logic and validations

### Events and SSE

- module/events/appEvents.js provides a central EventEmitter for app-level events
- routes/router_client_events.js provides SSE for clients and exposes sendEvents()
- message board and manage/product flows trigger SSE refresh events

### Localization

- module/localization/LocalizationService.js loads ui/*.json
- language switch via GET /lang/:lang stores lang in session

## Core Workflows

### Staff Login and App UI

1. GET / renders login view unless session.userid exists
2. POST /login validates username/password and creates session
3. GET /app loads base UI and requests component HTML and data from /app routes

### Client Order Flow

1. POST /client/searchName (nickname or name search)
2. POST /client/userLogin (client details)
3. POST /client/requestOrderPage (builds confirmation HTML and totals)
4. POST /client/placeOrder (writes order and updates client sum)
5. POST /client/deleteLastOrderConfirm and /client/deleteLastOrder for rollbacks

### Management Flow

1. GET /manage renders manage UI
2. Product CRUD: /manage/getProducts, /insertProduct, /editProduct, /deleteProduct
3. Client CRUD: /searchNameManage, /insertClient, /editClientFields, /deleteClient
4. Reporting: /getAllData, /getUserOrders, /getListOfArchiveReport

### Accounting Flow

1. GET /accountant renders accountant UI
2. Data queries: /getAllData, /requestReportArchive
3. CSV report generation: /createFileReportOrders, /createFileReportClients
4. Maintenance: /backupTable, /removeOldBackups, /resetClientsDataAfterRead

### Message Board Flow

1. GET /mboard/openBoard renders board HTML
2. POST /mboard/insertPost adds a post and triggers SSE reload
3. POST /mboard/insertImage uploads image and posts
4. Bots: chatbot and photobot are triggered by special text markers
5. QR flow creates temporary remote login links

## Code Style and Patterns

- Legacy routes: large routers, inline validation, direct db calls, mixed response types
- Refactored routes: thin routers + controllers + services + repositories + models
- Validation: legacy validatorClient middleware; new express-validator schemas in module/validation/schemas.js
- Errors: new middleware errorHandler and asyncHandler exist but are not wired into app.js
- Responses: new ResponseHelper standardizes JSON responses
- Logging: winston loggers for login, actions, orders, and message board events

## UI Surface

- EJS templates live in views/ (layout and page shells)
- HTML fragments are generated by module/html/* with buildHtml helpers
- public/ hosts css, js, images, and report output

## Current Gaps and Notes

- Refactored routers (router_*_refactored.js and router_client_controllers.js) are present but not mounted in app.js
- config/index.js provides validation and defaults but app.js still reads process.env directly
- Controller files under controllers/ use the new structure but are not fully wired to app.js
- Some controller imports appear to reference ../../functions instead of module/utils/functions.js
- SSE is used by management and message board flows; app-level event bridge is not wired to SSE
